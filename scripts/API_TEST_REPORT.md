- 此端點無法代替 mcgbm 的動態查詢功能

### 回傳格式重點

1. 外層是 `{"data": [...]}` 結構（不是純陣列）
2. 每筆含 `_id` 欄位（MongoDB ObjectId）
3. 包含巢狀欄位：`樓層概要`、`地號`、`門牌`（皆為陣列）
4. 發照日期格式：`"114年01月02日"`
5. 有 `qtime` 欄位（如 `"11401"`）標記查詢時間區間

## 四、查詢語法參考

### 基本格式

```
OpenDataSearchUrl.do?d=OPENDATA&c=BUILDLIC&Start=1&欄位=值
```

### 查詢範例

| 查詢目的 | 參數 |
|----------|------|
| 114年所有執照 | `&發照日期=114年` |
| 114年3月 | `&發照日期=114年03月` |
| 建造執照 | `&執照類別=建造執照` |
| 起造人姓王 | `&起造人代表人=王.*` |
| 特定地號 | `&地號.行政區=西屯&地號.地段=惠來段` |
| 特定門牌 | `&門牌.行政區=西屯區&門牌.路街段巷弄=台灣大道` |
| 分頁 | `&Start=101` (第 101~200 筆) |

### 執照類別

- 建造執照
- 使用執照
- 雜項執照
- 拆除執照

## 五、結論與建議

### 現況

1. **台中市建管系統 (`mcgbm.taichung.gov.tw`) 封鎖海外 IP**，TLS 層面直接 reset
2. 資料中心 (`datacenter.taichung.gov.tw`) 的建照 SERVICES 端點也無法正常查詢
3. API 格式本身沒有問題 — 彰化縣、基隆市使用相同格式已成功回傳資料

### 建議

1. **從台灣境內存取**：使用台灣 VPN 或部署在台灣的伺服器連線 `mcgbm.taichung.gov.tw`
2. **API 查詢設計**：查詢時務必帶條件（至少帶 `發照日期`），避免無條件查詢造成伺服器負擔
3. **分頁處理**：每次回傳上限 100 筆，需用 Start 參數迴圈取完所有資料
4. **資料時效性驗證**：待能成功連線後，查詢最近月份的資料，比對與前端查詢系統 (`bupic/pages/querylic`) 的結果是否一致
5. **錯誤處理**：需處理 `{"data": null}` 和空回傳的情況
